# awake-ui — Claude Code context

React component library published to npm as `@developmentsnil/awake-ui`.
Monorepo managed with **pnpm workspaces**.

## Structure

```
awake-ui/
├── src/                  # Library source
│   ├── theme.css         # Design tokens (@theme block — raw scales + semantic layer)
│   ├── dark-theme.css    # Dark mode overrides (semantic tokens only)
│   ├── styles.css        # Entry CSS (imports theme.css + all component CSS)
│   ├── <component>/
│   │   ├── index.tsx
│   │   ├── styles.css
│   │   └── <component>.stories.tsx
│   └── global.d.ts       # CSS module declarations
├── dist/                 # Build output (committed — published to npm)
├── playground/           # Vite app for manual testing (workspace: *)
│   └── src/App.tsx       # Showcases all components
├── package.json
├── tsup.config.ts        # JS bundler config
└── .storybook/           # Storybook config
```

## Commands

Run all commands from the **monorepo root** (`awake-ui/`).

| Task | Command |
|---|---|
| Build everything | `pnpm build` |
| Build JS only | `pnpm build:js` |
| Build main CSS | `pnpm build:css` |
| Copy dark-theme CSS | `pnpm build:dark-css` |
| Storybook dev | `pnpm storybook` |
| Playground dev | `pnpm --filter playground dev` |

> `build:dark-css` uses `cp` (not tailwindcss) because `dark-theme.css` contains only CSS custom properties — no Tailwind utilities.

## Architecture decisions

### Token system
Two-layer approach in `src/theme.css`:
1. **Raw scales** — full color palettes (`--color-awake-primary-*`, `--color-awake-neutral-*`)
2. **Semantic tokens** — what components actually reference (`--color-awake-brand`, `--color-awake-surface`, etc.)

Components **must** reference semantic tokens, never raw scales directly. This keeps customization simple: consumers override only semantic tokens.

### Dark mode
Centralized in `src/dark-theme.css` — a single file that overrides the semantic tokens. No `[data-theme="dark"]` blocks inside individual component CSS files.

### Component patterns
- **Compound components** — Dialog, Select, Table, Field, Tooltip, Switch all use the `{ Root, Trigger, … }` object export pattern.
- **`render` prop** — unstyled wrappers (Dialog.Trigger, Dialog.Close, Tooltip.Trigger) use Base UI's `render` prop for composition. They carry no visual style of their own.
- **CSS variable fallback** — components use `var(--awake-component-prop, var(--color-awake-semantic-token))` to allow per-instance overrides without losing the theme default.
- **`clsx`** — used for all className merging. No `cn()` utility.

### Styling
- Tailwind CSS v4 (`@theme {}` block, not `tailwind.config.js`)
- No `@apply` — explicit CSS properties only
- All class names are namespaced: `.awake-<component>-<element>`

## Adding a new component

1. Create `src/<name>/index.tsx` and `src/<name>/styles.css`
2. Add `import './styles.css'` inside `index.tsx`
3. Add the entry to `tsup.config.ts` (`entry` array)
4. Add the export to `package.json` (`exports` map)
5. Import the component CSS in `src/styles.css`
6. Create `src/<name>/<name>.stories.tsx`
7. Add the component to `playground/src/App.tsx`
8. Run `pnpm build` and verify `dist/` output

## What not to touch

- **`dist/`** — generated by build; only commit after running `pnpm build`
- **Raw scale tokens** in `theme.css` — change semantic tokens instead
- **`sideEffects`** in `package.json` — must list `dist/style.css` and `dist/dark-theme.css` so bundlers don't tree-shake them
